<task type="auto" tdd="true">
  <name>Task 2: processEvent — confirmação, dispatch, reporting</name>
  <files>apps/desktop/src/main/action-executor.ts, apps/desktop/src/main/__tests__/action-executor.test.ts</files>
  <behavior>
    - `processEvent(event)` interna:
      1. Resolve handler: `handler = deps.handlers[event.action]`. Se não existir → reporta `{success: false, error: 'unknown_action: ' + event.action}` via backendClient e retorna.
      2. Confirmation: se `event.requires_confirmation === true` OU `deps.requiresConfirmation.has(event.action)`:
         - Chama `await deps.dialog.showMessageBox({type: 'warning', buttons: ['Cancelar', 'Sim, executar'], defaultId: 0, cancelId: 0, title: 'Confirmar ação destrutiva', message: '...', detail: JSON.stringify(event.args)})`
         - Se `response !== 1` → reporta `{success: false, error: 'user_denied'}` e retorna.
      3. Invoca `const result = await handler(event.args)`.
      4. Reporta via `await backendClient.postToolCallResult(event.tool_call_id, result)`.
      5. Erros do backendClient são logados (`console.warn`) mas NÃO propagados — processEvent nunca lança, senão quebra a queue.
      6. Erros inesperados do handler (fora do contrato ActionResult) são capturados e reportados como `{success: false, error: 'handler_crash: ' + err.message}`.
    - Testes:
      - Action sem confirmation → handler + postToolCallResult chamados
      - Action com confirmation, user aprova (response=1) → handler + postToolCallResult chamados
      - Action com confirmation, user cancela (response=0) → handler NÃO chamado, postToolCallResult chamado com user_denied
      - Handler retorna success:false → postToolCallResult recebe o error
      - Handler lança exceção → postToolCallResult recebe handler_crash
      - backendClient.postToolCallResult lança → warn logado, queue continua
      - Action desconhecida → postToolCallResult recebe unknown_action
  </behavior>
