  <name>Task 1: Router tool-calls com proxy POST /tool-calls/:id/result</name>
  <files>apps/gateway/src/routes/tool-calls.ts, apps/gateway/src/app.ts, apps/gateway/src/config.ts, apps/gateway/src/__tests__/tool-calls.test.ts</files>
  <behavior>
    - `config.ts`: adiciona `apiKey: process.env.JARVIS_API_KEY` (optional string).
    - `routes/tool-calls.ts`: exporta `toolCallsRouter` Express Router com:
      - `POST /tool-calls/:id/result` handler:
        1. Valida `:id` é inteiro positivo. Senão 400 `{detail: 'invalid tool call id'}`.
        2. Monta URL upstream: `${config.fastapiUrl}/tool-calls/${id}/result`.
        3. Repassa headers: forwarda `Authorization` do request. Se ausente E `config.apiKey` presente → injeta `Bearer ${config.apiKey}` (defense in depth). Se ambos ausentes → segue sem auth (backend decidirá).
        4. Faz `fetch` com método POST, Content-Type: application/json, body = `JSON.stringify(req.body)`.
        5. Status 204 → `res.status(204).end()`.
        6. Status 400/404 → propaga status + body JSON do upstream.
        7. 5xx ou fetch erro → `next(Error)` com status 502 e code `UPSTREAM_ERROR`.
    - `app.ts`: `app.use('/api', toolCallsRouter)`.
    - Testes supertest com `nock` OU `vi.fn()` global fetch mockado:
      - 204 proxy
      - 400 invalid id (nunca bate no upstream)
      - 400 body inválido (upstream retorna 400, proxy repassa)
      - 404 upstream → 404 proxy
      - Authorization header forwardado
      - Sem Authorization mas com config.apiKey → injetado
      - Upstream network error → 502
  </behavior>
  <action>
Usar `undici.fetch` como o resto do gateway (ver `routes/chat.ts`). Pra testes, injetar `fetchImpl` via closure: exportar `createToolCallsRouter(fetchImpl?)` e passar mock nos testes. Sem nock novo. `createApp()` em `app.ts` pode receber overrides opcionais pra testes.

Validação de id: regex `^[1-9]\d*$` no path param antes de fazer o proxy.
  </action>
