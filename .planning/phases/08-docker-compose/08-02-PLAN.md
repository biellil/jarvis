  <action>
Create `docker-compose.yml` at repo root with this exact content (per D-05, D-06, D-07, D-08, D-09):

```yaml
services:
  python-service:
    build:
      context: .
      dockerfile: Dockerfile.python
    expose:
      - "8000"
    networks:
      - jarvis-net
    volumes:
      - ./data:/app/data
    env_file: .env
    extra_hosts:
      - "host.docker.internal:host-gateway"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health/ready"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 60s
    restart: unless-stopped

  gateway:
    build:
      context: .
      dockerfile: Dockerfile.node
    ports:
      - "3000:3000"
    networks:
      - jarvis-net
    env_file: .env
    environment:
      - FASTAPI_URL=http://python-service:8000
    depends_on:
      python-service:
        condition: service_healthy
    restart: unless-stopped

networks:
  jarvis-net:
    driver: bridge
```

Key decisions implemented:
- `expose: ["8000"]` NOT `ports:` on python-service (per D-05) — internal only
- `ports: ["3000:3000"]` on gateway (per D-05) — public entry point
- `extra_hosts: ["host.docker.internal:host-gateway"]` on python-service (per D-06) — Linux LM Studio access
- `./data:/app/data` volume on python-service (per D-07) — SQLite + ChromaDB persistence
- `env_file: .env` on both services (per D-08) — secrets at runtime, never in image
- `environment: FASTAPI_URL=http://python-service:8000` on gateway — overrides .env value for Docker DNS (per D-05)
- `healthcheck` with `start_period: 60s` on python-service (per D-09) — ChromaDB + sentence-transformers init
- `depends_on: condition: service_healthy` on gateway (per D-09) — waits for Python readiness
- `jarvis-net` bridge network — service name DNS resolution
- `restart: unless-stopped` on both — resilience

The `environment:` key on gateway overrides the `FASTAPI_URL` from `env_file: .env`, so local dev .env can keep `FASTAPI_URL=http://localhost:8000` while Docker uses the service name.
