  <behavior>
    - startWatching('/path/to/folder', cb): opens chokidar.watch with { ignoreInitial: true, persistent: true, depth: 0 }
    - On 'add' event: push { name: basename(filePath), path: filePath } into bufferFiles; reset debounce timer to 2000ms
    - When debounce fires: call onFolderEvent([...bufferFiles]); clear bufferFiles; debounceTimer = null
    - stopWatching(): clearTimeout(debounceTimer); await watcher.close(); watcher = null
    - startWatching called twice: await close() on existing watcher before opening new one
    - Error event from chokidar: console.error, do NOT rethrow (keep watching)
    - Test: single file added → onFolderEvent called after 2s with [{name, path}]
    - Test: 3 files added within 1s each → onFolderEvent called once after last file + 2s, with 3 entries
    - Test: stopWatching before timer fires → onFolderEvent NOT called
    - Test: startWatching twice with different paths → first watcher closed before second opens
  </behavior>
  <implementation>
    Create `apps/backend-ts/src/proactive/folder-watcher.ts` following the RESEARCH.md Pattern 3 example exactly.

    Key implementation details:
    - `import { watch as chokidarWatch, type FSWatcher } from 'chokidar'` — named import (ESM)
    - `path.basename(filePath)` to extract name (Node.js `path` module)
    - Use `NodeJS.Timeout` type for debounceTimer
    - Buffer is cleared AFTER copying to local array: `const files = [...this.bufferFiles]; this.bufferFiles = [];`
    - watcher.on('error') logs but does not rethrow — keeps watching per D-14

    For tests, use `vi.useFakeTimers()` to control the 2s debounce without waiting. Mock chokidar via `vi.mock('chokidar')` to avoid real filesystem operations. Pattern: mock `watch` to return a fake FSWatcher that manually triggers 'add' events.
