# Phase 28 — UI Design Contract

> Visual and interaction contract for multi-turn voice follow-up window.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase 28 scope:** After TTS response ends, automatically enter "listening window" state for N seconds, allowing user to ask follow-up questions without saying "Hey JARVIS".
> **Visual features:** New orb state, smooth timeout transition, VAD-based speech detection.

## Color

### Semantic State Colors (Orb Animation) — EXTENDED

Phase 28 adds 1 new orb state to the existing 4:

| State | Color | Tailwind Token | Hex | Usage | Source |
|-------|-------|----------------|-----|-------|--------|
| idle | Cyan ethereal | `cyan-500` | `#06B6D4` | Orb at rest, wake word active | Phase 11 |
| listening | Amber luminous | `amber-500` | `#F59E0B` | Recording user speech | Phase 11 |
| processing | Violet mystic | `violet-500` | `#8B5CF6` | Waiting for LLM response | Phase 11 |
| responding | Blue electric | `blue-500` | `#3B82F6` | TTS playing response | Phase 11 |
| **awaiting-followup** | **Blue softer** | **`sky-400`** | **`#0EA5E9`** | **Listening window post-TTS, awaiting next question** | **Phase 28 NEW** |

**Color rationale (D-10):** "Azul suave diferente do idle" — `sky-400` (#0EA5E9) is a lighter, less saturated blue than both idle cyan (#06B6D4) and responding blue (#3B82F6). Visually reads as "passive but attentive" — distinguishes clearly from idle (which has warm wake-word energy) and responding (which has active electric feel).

## Visual Effects (Aether Style Continuation)

### Orb State: `awaiting-followup`

**OrbContext type extension:**
```typescript
// Phase 28 addition to existing type
export type OrbState = 'idle' | 'listening' | 'processing' | 'responding' | 'awaiting-followup';
```

**Visual characteristics (D-11):**

1. **Color:** Sky-400 (#0EA5E9) glow instead of idle cyan
2. **Animation:** Slow constant pulsation (similar to idle breathing but slightly faster — indicates "waiting")
3. **Glow:** Drop-shadow at 60% opacity, same pattern as other states but with sky-400 RGBA
4. **Opacity:** Full opacity 1.0 (same as other states, unlike paused idle which uses 0.6)

### Animation Additions (Phase 28)

Add to `tailwind.config.ts`:

```javascript
animation: {
  // ... existing animations ...
  'pulse-followup': 'pulse-followup 1.5s ease-in-out infinite',  // D-11: slower pulsation than listening, faster than idle
},
keyframes: {
  // ... existing keyframes ...
  'pulse-followup': {
    '0%, 100%': { transform: 'scale(1)', opacity: '1' },
    '50%': { transform: 'scale(1.06)', opacity: '0.92' },
  },
},
```

**Rationale:** `pulse-followup` bridges idle (2s, minimal pulse) and listening (1s, aggressive pulse). 1.5s timing + 1.06 scale reads as "gently waiting" — slower than listening's eagerness, faster than idle's rest.

### Glow Effect for `awaiting-followup`

Add to `tailwind.config.ts`:

```javascript
boxShadow: {
  // ... existing shadows ...
  'orb-followup': '0 0 24px rgba(14, 165, 233, 0.6), 0 0 48px rgba(14, 165, 233, 0.4)',
},
```

### Transition to `awaiting-followup` (D-05, D-06)

**Fade suave without harsh keyframes:** When exiting `responding` state and entering `awaiting-followup`:
- Use existing crossfade mechanism from Phase 25 (ORB-POL-04)
- Gradient transition + opacity transition at 400ms (consistent with responding→idle)
- No new keyframe needed — reuse existing gradient swap + timing

**Timer pause on app minimize (D-06):**
- When app loses focus (`window.onblur`), pause the multi-turn timer
- When app regains focus (`window.onfocus`), resume timer from remaining duration
- Implementation: managed in `useMultiTurnWindow` hook, not in Orb component itself

### Reduced Motion Support (D-12)

Apply to all Phase 28 animations:

```css
@media (prefers-reduced-motion: reduce) {
  .animate-pulse-followup {
    animation: none;
    opacity: 0.95;  /* Subtle static fade instead of pulse */
  }
}
```

**Pattern:** Consistent with Phase 23 (ORB-POL-01). Users with reduced-motion preference see stable sky-400 color at 95% opacity instead of pulsing.

## Phase-Specific Notes

### Scope Boundaries

**Included:**
- Orb visual state extension (4 states → 5 states)
- Listening window post-TTS (timer-based)
- VAD speech detection within window (reusing @ricky0123/vad-web from Phase 24)
- Silent timeout transition back to idle
- Pause wake word during follow-up window (prevents double-activation)

**Excluded:**
- Backend changes (follow-up is renderer-only)
- Barge-in during TTS (out of scope — defer to future phase)
- Multi-turn context persistence (out of scope — CONV memory is Phase 27)
- Cancelation UI (timeout is silent, no button to stop waiting)

### Renderer Implementation Pattern

**Hook-based architecture (established Phase 22-24):**

1. `useMultiTurnWindow` — orchestrates timer, VAD, state transitions
   - Input: `isEnabled: boolean`, `windowMs: number` (from VITE_MULTI_TURN_WINDOW_MS)
   - Output: triggers `orbContext.setState('awaiting-followup')`, monitors VAD, resets to idle on timeout
   - Cleanup: clears timers on unmount

2. Integration point: `registerTTSHooks` afterPlay callback
   - After TTS finishes: delay 200-300ms, then activate multi-turn window
   - (Pattern: existing TTS hook infrastructure, just add new callback chain)

3. Voice pipeline: `sendAudioAndHandle` accepts `source: 'followup'` tracking
   - Already structured for 'ptt' | 'wakeword' | 'followup' variants
   - No new function needed, just parameter extension
