<behavior_contract>
**Happy path (success response, TTS plays):**
1. `setState('processing')` called first
2. `window.jarvis.sendAudio(audioBuffer)` called with the exact `Uint8Array` passed in
3. `setState('responding')` called (because `result.success === true`)
4. `handleAudioResponse(result, { addHumanMessage, addAgentMessage, setToast, playTTS: playTTSResponse })` called
   - This internally calls `addHumanMessage(result.data.transcription)` then `addAgentMessage(result.data.message)` BEFORE `playTTS`. So even if playTTS fails, the text is visible (D-06).
5. `setState('idle')` called (in finally or after await)

**Backend error path (result.success === false):**
1. `setState('processing')` called
2. `window.jarvis.sendAudio(audioBuffer)` returns `{ success: false, error: { code, message } }`
3. `setState('responding')` is NOT called
4. `handleAudioResponse(result, deps)` is still called — it will call `setToast` with the mapped pt-BR error message internally
5. `setState('idle')` called

**Thrown exception path (network unreachable, IPC crash):**
1. `setState('processing')` called
2. `window.jarvis.sendAudio(...)` throws (or handleAudioResponse throws unexpectedly)
3. Caught in try/catch
4. `setToast({ message: 'Erro inesperado ao enviar áudio.', variant: 'error' })` called
5. `setState('idle')` called in finally (ALWAYS called — no leaked 'processing' state)

**Key invariant:** `setState('idle')` MUST always be the final state — no code path leaves the orb stuck in processing or responding.
</behavior_contract>

<d06_vs_d08_clarification>
**D-06 (TTS failure graceful degrade):** When the LLM response text arrives successfully but audio playback fails (empty base64, player crash, codec error):
- `handleAudioResponse` ALREADY handles this correctly — it calls `addAgentMessage(result.data.message)` BEFORE awaiting `playTTS`. If `playTTS` throws, the text is already in the chat history.
- The existing `handleAudioResponse` emits a `warning` toast "Resposta pronta, mas não consegui tocar o áudio." via `setToast`. 
- **D-06 literal reading:** "orb transiciona para responding brevemente e retorna a idle normalmente. Sem toast de erro."
- **Research §"Shared Audio Pipeline Integration" note:** The existing warning toast is a deliberate UX signal ("resposta pronta mas TTS falhou — você viu o texto, não o áudio") and matches PTT behavior already shipped in v1.3 Phase 19.5.
- **Decision for Phase 24:** Keep `handleAudioResponse`'s current warning-toast behavior unchanged (consistency with PTT). The D-06 "no toast" is a soft-aspiration — the warning is informational, not blocking, and the user still sees the agent text. If UAT shows this as noise, fix via gap closure.

**D-08 (hard errors — backend down, LLM timeout, silent stream):** These come back as `SendAudioResponse.success === false` with an error code, or as thrown exceptions. `handleAudioResponse` already maps error codes to pt-BR messages via `mapErrorCode` (see `lib/errorMessages`). `sendAudioAndHandle` does NOT need to re-map — it delegates.

**Scope rule:** `sendAudioAndHandle` is a thin orchestrator. It does NOT reimplement toast mapping, message formatting, or TTS playback. All domain logic stays in `handleAudioResponse`.
</d06_vs_d08_clarification>

    ```typescript
    /**
     * sendAudioAndHandle — Phase 24 Plan 02 (D-07)
     *
     * Pure async function that encapsulates the renderer-side audio → LLM → TTS
     * pipeline. Consumed by:
     *   - `ChatInput.tsx` (PTT flow) — replaces inline block linhas 75-124
     *   - `useWakeWord.ts` (wake word flow) — replaces discarded stopRecording bytes
     *
     * Contract (D-07 + D-08 + D-06):
     *   1. setState('processing') immediately
     *   2. Call window.jarvis.sendAudio(audioBuffer)
     *   3. On success → setState('responding') then delegate to handleAudioResponse
     *      (which calls addHumanMessage + addAgentMessage BEFORE playTTS, so
     *      text survives TTS failures — D-06 graceful degrade)
     *   4. On error response → handleAudioResponse maps error code to pt-BR toast
     *   5. On thrown exception → generic pt-BR toast + state cleanup
     *   6. INVARIANT: setState('idle') is always the last state transition
     *
     * Design: zero internal state, deps injected for testability. NOT a hook
     * (useVoiceRequest hook explicitly rejected in D-07 in favor of pure function).
     */
    import type { SendAudioResponse } from '../../../shared/ipc-types';
    import type { OrbState } from '../../components/Orb/OrbContext';
    import { handleAudioResponse, type ToastState } from './handleAudioResponse';
    import { playTTSResponse } from '../audio/ttsPlayer';

    export interface SendAudioAndHandleDeps {
      /** Orb state setter — transitions processing → responding → idle */
      setState: (state: OrbState) => void;
      /** Toast setter — pt-BR error messages on failure */
      setToast: (toast: ToastState | null) => void;
      /** Chat history: appends user transcription after successful STT */
      addHumanMessage: (text: string) => void;
      /** Chat history: appends agent response BEFORE playTTS (D-06 degrade) */
      addAgentMessage: (text: string) => void;
    }

    export async function sendAudioAndHandle(
      audioBuffer: Uint8Array,
      deps: SendAudioAndHandleDeps,
    ): Promise<void> {
      deps.setState('processing');
      try {
        const result: SendAudioResponse = await window.jarvis.sendAudio(audioBuffer);

        if (result.success) {
          deps.setState('responding');
        }

        // handleAudioResponse handles BOTH success (text + TTS) and failure
        // (pt-BR toast via mapErrorCode). D-06 degrade is inside it:
        // addAgentMessage runs BEFORE playTTS, so text survives TTS errors.
        await handleAudioResponse(result, {
          addHumanMessage: deps.addHumanMessage,
          addAgentMessage: deps.addAgentMessage,
          setToast: deps.setToast,
          playTTS: playTTSResponse,
        });
      } catch (err) {
        console.error('[sendAudioAndHandle] unexpected error:', err);
        deps.setToast({
          message: 'Erro inesperado ao enviar áudio.',
          variant: 'error',
        });
      } finally {
        // INVARIANT: always return to idle. Prevents orb stuck in processing/responding
        // if any downstream call throws mid-flight.
        deps.setState('idle');
      }
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer React component → `window.jarvis.sendAudio` IPC | Renderer passes `Uint8Array` to main process via preload bridge. Main process enforces size limits + retries. Trust boundary is the IPC channel. |
| `sendAudioAndHandle` → `handleAudioResponse` | Internal function call within renderer. No trust boundary. |
| `handleAudioResponse` → `playTTSResponse` | Internal, but `playTTS` crashes are expected (codec errors, autoplay policy). Must not leak the orb state. |
