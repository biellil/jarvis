<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: End-to-end memory verification across sessions</name>
  <what-built>
    Complete memory system: SQLite persistence (conversations, messages, summaries, user_profile tables), ChromaDB semantic recall (sentence-transformers all-MiniLM-L6-v2 embeddings), user profile extraction (explicit triggers + LLM-based implicit extraction), rolling summary compression, system prompt augmentation with profile facts, and save-on-exit via try/finally.
  </what-built>
  <how-to-verify>
    **Prerequisites:** Ensure an LLM is running (LM Studio with a model loaded, or cloud provider configured in .env).

    **Test 1 -- Session persistence and save on exit (MEM-01 + MEM-02):**
    1. Run `PYTHONPATH=src python3 -m jarvis`
    2. Have a 2-3 turn conversation about any topic
    3. Press Ctrl+C to exit
    4. Verify you see "Memorias salvas." in output
    5. Run: `sqlite3 data/jarvis.db "SELECT COUNT(*) FROM conversations;"` -- expect >= 1
    6. Run: `sqlite3 data/jarvis.db "SELECT COUNT(*) FROM messages;"` -- expect >= 4 (2 user + 2 assistant minimum)

    **Test 2 -- User profile storage (MEM-03):**
    1. Run `PYTHONPATH=src python3 -m jarvis`
    2. Say: "lembra que eu prefiro codigo em Python"
    3. Wait for JARVIS response, then Ctrl+C
    4. Run: `sqlite3 data/jarvis.db "SELECT key, value, source FROM user_profile;"` -- expect at least one row with source="explicit"
    5. Run: `ls -la data/chroma/` -- expect ChromaDB files exist

    **Test 3 -- Profile injection in new session (MEM-04):**
    1. Run `PYTHONPATH=src python3 -m jarvis` (new session after Test 2)
    2. Ask JARVIS to write some code (without specifying language)
    3. Expected: JARVIS writes Python code (influenced by stored preference from Test 2)
    4. If JARVIS doesn't use Python, the profile injection may not be working

    **Test 4 -- Past session recall (MEM-05):**
    1. In the same session as Test 3, ask: "voce lembra o que conversamos antes?"
    2. Expected: JARVIS references content from the earlier sessions (Test 1 and/or Test 2 topics)
    3. This verifies ChromaDB semantic retrieval is surfacing past messages

    **Test 5 -- Graceful error handling (MEM-05 safety):**
    1. Check that no Python tracebacks appeared during any of the tests
    2. All memory operations should be silent on error (logged, not shown to user)
  </how-to-verify>
  <resume-signal>Type "approved" if all 5 tests pass, or describe which test(s) failed and what happened.</resume-signal>
</task>
