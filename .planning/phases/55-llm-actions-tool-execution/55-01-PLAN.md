# Plan 55-01: Electron OS Action Execution

## Objective

Implement the Electron-side OS action handlers for the 4 LLM file actions
(`openFolder`, `openFile`, `closeFile`, `viewContent`) and extend the
IPC/ACK pipeline so that the renderer executes the action before sending
the ACK — with the ACK carrying file content for `viewContent` actions.

## Context

@apps/desktop/src/renderer/src/hooks/useActionConfirmation.ts
@apps/desktop/src/shared/ipc-types.ts
@apps/gateway/src/lib/path-validator.ts

## Tasks

### Task 1: Extend IPC types for execution channel

Add to `apps/desktop/src/shared/ipc-types.ts`:
- `ACTION_EXECUTE` IPC channel (renderer → main): renderer sends `{requestId, action, path}` after user confirms toast; main executes OS action and returns result
- `ActionExecutePayload` type: `{ requestId: string; action: FileAction; path: string }`
- `ActionExecuteResult` type: `{ success: boolean; content?: string; error?: string }` — `content` populated only for `viewContent`
- Extend `JarvisAPI.actions` with `execute(payload: ActionExecutePayload): Promise<ActionExecuteResult>`
- Add `ACTION_EXECUTE: 'actions:execute'` to `IPC_CHANNELS`

**Done when:** Types compile with no errors.

### Task 2: Implement OS action handlers in Electron main

Create `apps/desktop/src/main/actions/file-actions.ts`:
- `openFolderHandler(path: string): Promise<ActionExecuteResult>` — uses `shell.openPath(path)`, returns `{ success: true }` or `{ success: false, error: errorMsg }`
- `openFileHandler(path: string): Promise<ActionExecuteResult>` — uses `shell.openPath(path)` (Electron opens files in default app)
- `closeFileHandler(processName: string): Promise<ActionExecuteResult>` — uses `runExecFile` with `taskkill /IM <name> /F` (Windows) or `pkill -f <name>` (macOS/Linux) via `process.platform`; `processName` is what was passed as `path` field per D-07
- `viewContentHandler(filePath: string): Promise<ActionExecuteResult>` — reads file with `fs.promises.readFile`, enforces 1MB limit (D-04), returns `{ success: true, content: text }` or `{ success: false, error }` on oversized/unreadable

Create `apps/desktop/src/main/actions/file-action-dispatcher.ts`:
- `dispatchFileAction(action: FileAction, path: string): Promise<ActionExecuteResult>` — routes to the correct handler above

**Done when:** All 4 handlers implemented and exported; `dispatchFileAction` compiles.

### Task 3: Register IPC handler in main process

In `apps/desktop/src/main/ipc/` — create `fileActions.ts`:
- `setupFileActionHandlers()`: registers `ipcMain.handle(IPC_CHANNELS.ACTION_EXECUTE, async (_, payload) => { ... })` 
- Validates payload shape, calls `dispatchFileAction`, returns `ActionExecuteResult`
- Imports `dispatchFileAction` from `file-action-dispatcher.ts`

Wire it in `apps/desktop/src/main/index.ts` (or wherever other IPC handlers are registered via `setup*Handlers` calls).

**Done when:** `setupFileActionHandlers` call present in main entry, TypeScript compiles.

### Task 4: Expose execute via preload

In `apps/desktop/src/preload/index.ts` (or wherever `window.jarvis.actions` is defined):
- Add `execute: (payload) => ipcRenderer.invoke(IPC_CHANNELS.ACTION_EXECUTE, payload)` to the `actions` contextBridge object

**Done when:** `window.jarvis.actions.execute` is available to renderer.

### Task 5: Update useActionConfirmation to execute before ACK

Update `apps/desktop/src/renderer/src/hooks/useActionConfirmation.ts`:
- Replace `sendAck` with `confirmAction(requestId, action, path)`:
  1. Calls `window.jarvis.actions.execute({ requestId, action, path })`
  2. On success → calls `window.jarvis.actions.sendAck(requestId, 'confirmed')`; on failure → sends `'denied'`
- `denyAction(requestId)` — sends ACK `'denied'` immediately (no execute)
- Update `PendingAction` if needed
- Update callers: `ActionConfirmationToast` in `App.tsx` uses `confirmAction`/`denyAction`

**Done when:** Hook compiles, existing tests pass.

### Task 6: Extend actionsClient to forward content in ACK

Currently `sendActionAck` in `actionsClient.ts` sends `{ type: 'action_ack', requestId, status }`.
Per D-01, extend to carry `content` for viewContent:

- Update `sendActionAck(requestId, status, content?: string)` signature
- Update WS send to include `content` field when provided: `{ type: 'action_ack', requestId, status, content }`
- Update `ActionAckPayload` in `ipc-types.ts` to include `content?: string`

Also update `ActionAckSchema` in `apps/gateway/src/lib/path-validator.ts`:
- Add `.extend({ content: z.string().optional() })` to the schema
- Update `ActionAck` type accordingly

**Done when:** ACK wire format carries content; both Electron client and gateway schema compile.

### Task 7: Unit tests for file action handlers

Create `apps/desktop/src/main/actions/__tests__/file-actions.test.ts`:
- Test `openFolderHandler`: mock `shell.openPath`, assert ok result
- Test `openFileHandler`: mock `shell.openPath`, assert ok result
- Test `closeFileHandler`: mock `runExecFile`, test Windows path (taskkill) and non-Windows path (pkill)
- Test `viewContentHandler`: mock `fs.promises.readFile`, test: normal file, file > 1MB (denied), readFile error (denied)
- All tests use vi.mock for electron shell and fs

**Done when:** `pnpm --filter desktop test` passes with no new failures.
