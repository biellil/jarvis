# Phase 42 — UI Design Contract

> Visual and interaction contract for Orb Per-Mode Visual Identity. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope

**IN scope (UI):**
- Orb idle gradient/glow distinct per VoiceMode (VUI-02)
- Persistent compact mode badge on orb ("WW" / "AL" / "PTT") (VUI-03)
- Mode-switch confirmation toast via existing Toast component (VUI-03, < 500ms)
- No flash of wrong mode on app restart (correct color/badge from first frame)

**OUT of scope:**
- Settings UI changes (Phase 40 owns slider)
- Tray menu radio state (Phase 41 owns)
- PTT-only strategy wiring (Phase 43 owns)

  'wake-word':       '#7BE8F5',

  'ptt-only':        'rgba(254,215,170,0.35)',

### Badge Visibility Rules

- Badge is ALWAYS visible (all orb states: idle, listening, processing, responding, awaiting-followup).
- Badge color is always the mode's idle palette color — it does NOT change per orb state. This provides stable mode identification regardless of what JARVIS is doing.
- `pointerEvents: 'none'` — never intercepts mouse events (drag-to-reposition must work through the badge area).

## Component: Mode-Colored Idle Orb (Extension of Orb.tsx)

### Design Contract for `stateGradients` Extension

The existing `stateGradients` and `stateGlow` Records in `Orb.tsx` are keyed by `OrbState`. Phase 42 introduces a secondary axis: when `state === 'idle'`, the gradient and glow are further determined by `voiceMode`.

**Implementation approach:** Pass `voiceMode: VoiceMode` prop from OrbContext (or directly from App.tsx state) into Orb. Orb computes the active idle gradient/glow based on voiceMode. Non-idle states are unchanged — same gradients as today.

### Crossfade Behavior

The existing 400ms crossfade mechanism (sublayer A/B, `displayedGradients` state in Orb.tsx) is reused for mode-color transitions. When voiceMode changes while orb is idle, the crossfade triggers just as it would for a state change: `from` = previous mode idle gradient, `to` = new mode idle gradient.

Transition duration: 400ms ease-in-out (existing `transition: 'opacity 400ms ease-in-out'`).

This means: the mode-color update is visually smooth — no flash.

### No-Flash on Restart (VUI-02 SC4)

The `voiceMode` value must be read from `window.jarvis.voiceMode.getMode()` before the first render paint. The correct approach:

1. `OrbContext` (or App.tsx) fetches `voiceMode` via `window.jarvis.voiceMode.getMode()` on mount.
2. Initial `useState` for `voiceMode` is set to `null` (loading) — during this window (<10ms, synchronous Electron IPC), the orb renders with the wake-word idle gradient as a safe default (not a blank/white flash).
3. Once the promise resolves, `setVoiceMode(m)` fires — if the stored mode is already `wake-word`, zero visual change. If it's `always-listening` or `ptt-only`, the orb crossfades within the first render cycle.

**Safe default during loading:** `'wake-word'` — renders existing blue idle. This is the correct behavior for v1.8 migrated users and new installs.

## Component: Mode-Switch Confirmation Toast

### Contract

Uses the **existing** `Toast` component (no new component). Called via `setToast()` from `ChatContext` (same pattern as Phase 44 mic-permission toast).

Phase 42 adds the **success** branch to the existing `voice-mode:switch-result` handler in `App.tsx`. Currently, App.tsx only handles `success: false` with `blockedReason === 'mic-permission-denied'`. Phase 42 extends it to handle `success: true`.

### Toast Spec

| Property | Value |
|----------|-------|
| `message` | `"Modo: {label}"` where `label` is `VoiceModeSwitchResult.label` from IPC payload |
| `variant` | `'info'` |
| `autoCloseMs` | `2000` (2 seconds — overrides Toast default 5000) |
| `action` | `undefined` (no action button for confirmation toast) |

**< 500ms requirement:** The IPC path is: tray click → `broadcastModeSwitch()` → `ipcRenderer.on('voice-mode:switch-result')` → React `setToast()`. This is a direct IPC event delivery — no async gap beyond Electron IPC round-trip (~5–15ms). The `setToast` call in the handler fires synchronously on the IPC callback. React's setState batching with Electron's synchronous main-process IPC guarantees < 500ms.

### Extended Handler in App.tsx

```typescript
// Phase 42 extension: handle success:true branch
const handleSwitchResult = (
  _event: unknown,
  result: VoiceModeSwitchResult,
) => {
  if (result.success && result.label) {
    setToast({
      message: `Modo: ${result.label}`,
      variant: 'info',
    });
    // autoCloseMs is passed at render time, not in ToastState — handled in JSX
  } else if (!result.success && result.blockedReason === 'mic-permission-denied') {
    setToast({
      message: 'Microfone negado — abrir configurações?',
      variant: 'warning',
      action: {
        label: 'Abrir System Settings',
        onClick: () => window.jarvis.openSystemSettings?.(),
      },
    });
  }
};
```

**Toast render in App.tsx JSX** (existing pattern, no change to structure):
```jsx
{toast && (
  <Toast
    message={toast.message}
    variant={toast.variant}
    action={toast.action}
    autoCloseMs={toast.action ? 0 : 2000}  // Phase 42: change from undefined to 2000 for mode-switch toasts
    onClose={() => setToast(null)}
  />
)}
```

**Rationale for 2000ms vs existing 5000ms default:** Mode confirmation is a low-signal notification (confirms an action the user just initiated). 2s clears the view quickly. Phase 44 permission toast uses `autoCloseMs={0}` (manual dismiss) because it requires user action — that behavior is preserved via the `toast.action ? 0 : 2000` ternary.

## OrbContext Extension: voiceMode

`OrbContext` needs to expose `voiceMode` so `Orb.tsx` can compute the idle gradient and badge color without prop-drilling through App.tsx.

### Addition to OrbContextValue

```typescript
interface OrbContextValue {
  state: OrbState;
  setState: (newState: OrbState) => void;
  wakeWordPaused: boolean;
  setWakeWordPaused: (paused: boolean) => void;
  burstActive: boolean;
  triggerWakeBurst: () => void;
  // Phase 42 (VUI-02, VUI-03): current voice mode — drives idle color and badge
  voiceMode: VoiceMode;
  setVoiceMode: (mode: VoiceMode) => void;
}
```

**Default value in OrbProvider:**
```typescript
const [voiceMode, setVoiceMode] = useState<VoiceMode>('wake-word');
```

**Initialization in OrbProvider (useEffect on mount):**
```typescript
useEffect(() => {
  void window.jarvis.voiceMode?.getMode().then((m) => {
    if (m) setVoiceMode(m);
  });
  const unsub = window.jarvis.voiceMode?.onChange((evt) => {
    setVoiceMode(evt.newMode);
  });
  return () => { unsub?.(); };
}, []);
```

**Decision rationale:** Moving voiceMode subscription into OrbProvider (rather than App.tsx) keeps all orb visual state colocated. App.tsx already has a voiceMode subscription for gating WakeWordFeatures — Phase 42 does NOT remove that subscription (it serves a different purpose: gating hooks, not visual state). The two subscriptions are independent and both use `window.jarvis.voiceMode.onChange`, which supports multiple listeners.

## Interaction States

### Orb Idle State — Per-Mode

| VoiceMode | Gradient | Glow | Badge text | Badge border |
|-----------|----------|------|------------|--------------|
| `wake-word` | Blue (existing) | `rgba(43,168,212,0.55)` | `WW` in `#7BE8F5` | `rgba(123,232,245,0.35)` |
| `always-listening` | Green (new) | `rgba(34,197,94,0.55)` | `AL` in `#86EFAC` | `rgba(134,239,172,0.35)` |
| `ptt-only` | Orange (new) | `rgba(249,115,22,0.55)` | `PTT` in `#FED7AA` | `rgba(254,215,170,0.35)` |

### Orb Non-Idle States — Unchanged

When orb state is `listening`, `processing`, `responding`, or `awaiting-followup`: existing gradients/glow apply regardless of voiceMode. Badge remains visible with the mode's idle color (badge does not change color based on orb state — only based on voiceMode).

### Paused Visual (wakeWordPaused)

When `state === 'idle' && wakeWordPaused === true`: existing reduced-opacity behavior (`opacity: 0.6`, `glowRadius: 12`, `glowRgba: 'rgba(43,168,212,0.28)'`) still applies. This override is specific to wake-word mode (wakeWordPaused is only set in wake-word mode). Badge opacity follows the root `rootOpacity` (0.6 when paused).

### Mode Transition Animation

When voiceMode changes while `state === 'idle'`:
1. Existing crossfade kicks in (400ms, sublayer A/B)
2. Badge color transitions via CSS `transition: 'color 0.4s ease-in-out, border-color 0.4s ease-in-out'`
3. Drop-shadow glow changes via existing `transition: 'filter 0.4s ease-in-out'`

All three transitions run in parallel at 400ms — unified visual transition.

## Runtime Behavior

### Initialization Sequence (No-Flash Guarantee)

1. `OrbProvider` mounts → `useState<VoiceMode>('wake-word')` initializes with safe default
2. Orb renders with blue idle gradient on first frame (correct for most users; acceptable for others)
3. `useEffect` fires after first render → `window.jarvis.voiceMode.getMode()` is invoked
4. Promise resolves (Electron IPC: ~5–15ms) → `setVoiceMode(m)` triggers re-render
5. If `m !== 'wake-word'`, crossfade starts from blue → correct mode color (400ms)
6. Because this happens within the first few milliseconds after mount, no user perceives a "flash" — the window is still opening/fading in

**Alternative considered:** Reading voiceMode synchronously via a synchronous IPC call before React mount. Rejected — Electron contextBridge does not support synchronous invoke. The 15ms async gap is imperceptible during window open animation.

### Mode Change at Runtime

1. User clicks tray menu → VoiceModeManager.setMode() → broadcastModeSwitch()
2. Main emits `voiceMode:change` (picked up by OrbProvider subscriber → setVoiceMode)
3. Main emits `voice-mode:switch-result` (picked up by App.tsx handler → setToast)
4. Both fire in the same IPC tick — toast and badge/gradient update together
5. Orb crossfades idle gradient (400ms) + badge color transitions (400ms) in parallel
6. Toast appears immediately at bottom-center, auto-dismisses after 2000ms

## Accessibility

### Badge

```jsx
<div
  role="status"
  aria-label={`Voice mode: ${voiceModeLabelFull[voiceMode]}`}
  aria-live="polite"
  // ... styles
>
  {modeBadgeLabel[voiceMode]}
</div>
```

`aria-live="polite"` announces badge changes to screen readers without interrupting. `aria-label` provides the full mode name ("Voice mode: Always-Listening") instead of the abbreviated text ("AL").

### Toast

Existing `role="alert"` on Toast component announces mode-switch confirmation to screen readers. No changes needed.

### Color Contrast

Badge text on `rgba(0,0,0,0.55)` background:
- Wake Word `#7BE8F5` on `#000`: contrast ratio ~8.4:1 — WCAG AA large text pass
- Always-Listening `#86EFAC` on `#000`: contrast ratio ~9.2:1 — WCAG AA large text pass
- PTT-only `#FED7AA` on `#000`: contrast ratio ~8.6:1 — WCAG AA large text pass

All three pass at the 10px/semibold size used. (WCAG requires 4.5:1 for normal text, 3:1 for large text. At 10px these are treated as normal text — ratios exceed 4.5:1.)
