<objective>
Wire the confirmation bypass: read-only actions (openFolder, openFile, viewContent) auto-execute inside useActionConfirmation without ever setting pendingAction (so no toast appears). Destructive actions (deleteFile, moveFile, renameFile) continue through the existing pendingAction → toast → user confirm flow.

Purpose: FACT-10 requires read-only actions to execute instantly without interrupting the user. FACT-11 requires destructive actions to retain the 10s confirmation toast. This plan implements the behavioral split at the hook level, which is the correct chokepoint: all ACTION_REQUEST payloads arrive there first.

Output: Updated useActionConfirmation (auto-execute read-only), updated ActionConfirmationToast (correct labels for new actions), updated App.tsx (no changes to toast render logic needed — it already renders based on pendingAction being non-null), and new tests validating the bypass.
</objective>

REPLACE the useEffect block (the one with unsub = window.jarvis.actions?.onRequest) with:
```typescript
  useEffect(() => {
    const unsub = window.jarvis.actions?.onRequest(async (payload: ActionRequestPayload) => {
      // FACT-10: Read-only actions execute immediately — no confirmation toast
      if (READ_ONLY_ACTIONS.has(payload.action)) {
        try {
          const result = await window.jarvis.actions?.execute({
            requestId: payload.requestId,
            action: payload.action as import('../../../shared/ipc-types.js').FileAction,
            path: payload.path,
          });
          if (result?.success) {
            await window.jarvis.actions?.sendAck(payload.requestId, 'confirmed', result.content);
          } else {
            console.warn('[useActionConfirmation] read-only auto-execute failed', { payload, error: result?.error });
            await window.jarvis.actions?.sendAck(payload.requestId, 'denied');
          }
        } catch (err) {
          console.error('[useActionConfirmation] read-only auto-execute threw', err);
          await window.jarvis.actions?.sendAck(payload.requestId, 'denied');
        }
        return; // Do NOT set pendingAction — no toast for read-only
      }

      // FACT-11: Destructive actions (deleteFile, moveFile, renameFile) show confirmation toast
      // Replace any existing pending action (only one toast at a time)
      setPendingAction({
        requestId: payload.requestId,
        action: payload.action,
        path: payload.path,
        model: payload.model,
      });
    });

    return () => unsub?.();
  }, []);
```

NOTE: The useEffect dependency array remains `[]` — onRequest callback captures the stable window.jarvis.actions reference. The async callback in onRequest is fire-and-forget (no await at the call site) — this is correct because the gateway already has a 12s timeout on the request side.
