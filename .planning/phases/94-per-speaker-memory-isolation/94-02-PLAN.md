<objective>
Thread the x-jarvis-speaker header end-to-end: gateway → backend route → ChatSession → write path.

Purpose: After the schema exists (Plan 01), each new turn must record WHO said it. This plan wires the speaker identity from the desktop-py HTTP header through every hop to the SQLite insert and ChromaDB metadata. No filter logic yet — that's Plan 03.

Output:
- Gateway forwards x-jarvis-speaker on both chat routes (mirrors x-jarvis-client-id pattern)
- Backend chat.ts reads the header and calls session.setSpeaker()
- ChatSession gains setSpeaker() + exposes getSpeakerId() for the memory layer
- manager.saveTurn() and manager.saveTypedMemory() receive + write speakerId
</objective>
