Create Dockerfile.backend-ts with multi-stage build (per D-12, D-13, D-14 from CONTEXT.md):

```dockerfile
# Stage 1: Builder - includes build tools for native modules
FROM node:22-slim AS builder

WORKDIR /app

# Install build tools for native modules (better-sqlite3, @nut-tree-fork/nut-js in Phase 16/18)
RUN apt-get update && apt-get install -y \
    python3 \
    make \
    g++ \
    build-essential \
    libsqlite3-dev \
    && rm -rf /var/lib/apt/lists/*

# Copy package files
COPY apps/backend-ts/package.json ./
COPY apps/backend-ts/package-lock.json* ./

# Install all dependencies (including devDependencies for TypeScript compilation)
RUN npm install

# Copy source code
COPY apps/backend-ts/src ./src
COPY apps/backend-ts/tsconfig.json ./

# Compile TypeScript to JavaScript
RUN npx tsc

# Stage 2: Runtime - production only
FROM node:22-slim AS runtime

WORKDIR /app

# Install runtime dependencies for native modules and curl for health checks
RUN apt-get update && apt-get install -y \
    curl \
    libsqlite3-dev \
    && rm -rf /var/lib/apt/lists/*

# Copy package files
COPY --from=builder /app/package.json ./
COPY --from=builder /app/package-lock.json* ./

# Install production dependencies only
RUN npm install --omit=dev

# Copy compiled JavaScript from builder
COPY --from=builder /app/dist ./dist

# Set environment defaults
ENV NODE_ENV=production
ENV BACKEND_TS_PORT=8001

# Expose port (documentation only, not published)
EXPOSE 8001

# Start the server
CMD ["node", "dist/index.js"]
```

Key points:
- python3, make, g++, build-essential for native module compilation in builder stage
- libsqlite3-dev for better-sqlite3 support (future Phase 16)
- curl in runtime stage for Docker Compose health checks
- npm used in Docker (isolated from pnpm workspace) for simplicity

Add backend-ts service to docker-compose.yml (per D-16 through D-20 from CONTEXT.md):

```yaml
  backend-ts:
    build:
      context: .
      dockerfile: Dockerfile.backend-ts
    container_name: jarvis-backend-ts
    expose:
      - "8001"  # Internal only, not published until Phase 21
    networks:
      - jarvis-net
    volumes:
      - ./data:/app/data  # Prepared for SQLite/ChromaDB in Phase 16
    env_file: .env
    environment:
      - BACKEND_TS_PORT=8001
      - NODE_ENV=production
    extra_hosts:
      - "host.docker.internal:host-gateway"  # For LM Studio access
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8001/health"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 30s
    restart: unless-stopped
```

Add this service after the gateway service in docker-compose.yml. Key configurations:
- Port 8001 exposed internally only (not published with ports:)
- Same jarvis-net network as python-service and gateway
- Volume mount for ./data (future SQLite/ChromaDB persistence)
- Health check using curl with production-tested intervals (10s/5s/3/30s)
- extra_hosts for accessing LM Studio on host machine
