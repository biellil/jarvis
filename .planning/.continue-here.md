## O que fazer — 7 verificações manuais

Execute em ordem, cronometrando e anotando os resultados de cada uma.

### VERIFICAÇÃO 1 — WAKE-01 latência ≤500ms (smoke dev)

1. Confirme que os 4 modelos estão em `apps/desktop/resources/wakeword-models/`:
   ```
   ls apps/desktop/resources/wakeword-models/*.onnx | wc -l
   ```
   Esperado: `4`. Se não for: `node scripts/download-wakeword-models.mjs --force`.

2. Rode `pnpm --filter @jarvis/desktop dev`.
3. Aguarde o orb aparecer (estado idle).
4. Abra o DevTools (Ctrl+Shift+I) e verifique no console log tipo:
   `[wakeWord] engine started — threshold: 0.5 vadTimeoutMs: 3000`
   (sem erro de boot).
5. **Fale claramente**: "Hey JARVIS".
6. **Cronometre com smartphone**: tempo do fim de "JARVIS" até o orb transicionar para listening.
7. Esperado: orb vai para listening em **≤500ms** (WAKE-01).
8. Se latência > 500ms → FAIL — anote valor medido + investigue (possivelmente cold start do ORT, meça segunda tentativa).

### VERIFICAÇÃO 2 — WAKE-05 full cycle

1. Ainda em `pnpm dev`, orb em idle.
2. Fale "Hey JARVIS, que horas são?"
3. Esperado: orb idle → listening → processing → responding (TTS) → idle.
4. Após TTS terminar, aguarde ~1s.
5. Fale "Hey JARVIS, obrigado" novamente.
6. Esperado: segundo ciclo funciona igual ao primeiro (sem reiniciar o app).
7. Se o segundo "Hey JARVIS" não for detectado → FAIL (engine não resumiu após TTS — investigue logs do console).

### VERIFICAÇÃO 3 — WAKE-06 VAD timeout 3000ms

1. Fale "Hey JARVIS" (orb vai para listening).
2. Fique em silêncio por 4 segundos.
3. Esperado: orb volta para idle após ~3s (VITE_WAKE_WORD_VAD_TIMEOUT_MS=3000).
4. Se ficar travado em listening > 5s → FAIL.

### VERIFICAÇÃO 4 — WAKE-07 PTT preemption

1. Com orb em idle, fale "Hey JARVIS" + imediatamente pressione Ctrl+Space (PTT).
2. Esperado: PTT ganha — orb fica em listening, e quando soltar/pressionar PTT de novo, a captura é do PTT (não do wake word).
3. Verifique no console: log `[wakeWord] ignored — voiceInputManager: BUSY` ou equivalente.
4. Depois teste o inverso: pressionar PTT → falar → parar → wake word deve voltar a funcionar normalmente.

### VERIFICAÇÃO 5 — WAKE-08 Mic unavailable degrade

1. Em Windows: Settings → Privacy & security → Microphone → DESLIGAR acesso do app.
   (Linux: desligue via PulseAudio / `pactl` / alsamixer mute).
   (macOS: System Settings → Privacy → Microphone → desmarque Electron/JARVIS).
2. Reinicie JARVIS (`pnpm dev`).
3. Esperado:
   - Orb aparece normalmente;
   - PTT ainda funciona (Ctrl+Space);
   - Wake word NÃO dispara;
   - Console log: `[useWakeWord] boot failed — degrading to PTT-only ...`;
   - O app NÃO crasha.
4. Restaure a permissão de mic depois do teste.

### VERIFICAÇÃO 6 — WAKE-09 CPU budget sustained <2% (BLOCKING)

1. Com orb em idle, rode `pnpm --filter @jarvis/desktop dev`.
2. Abra:
   - Windows: Task Manager → Details tab;
   - macOS: Activity Monitor → CPU tab;
   - Linux: `htop` ou `top`.
3. Filtre/procure o processo `electron` ou `JARVIS` (especificamente o renderer — se houver múltiplos processos Electron, o renderer é geralmente o de maior PID ou o que tem maior memória).
4. **Deixe rodando em silêncio total por 10 minutos** (sem falar, música desligada, sem interagir).
5. Anote o CPU% médio da janela de 10min.
6. Esperado: **< 2% sustained**.
7. Se CPU >= 2% → **FAIL — bloqueante, não pode mergear**. Investigar:
   - VAD gate funcionando? Confira logs do console.
   - `numThreads=1` confirmado? (já travado no import do WakeWordEngine.)
   - Worklet cadência (12.5Hz) correta?
   - Aumentar `debounceMs` se estiver disparando muito?
   - Abra issue + rode `/gsd:plan-phase 22 --gaps`.

### VERIFICAÇÃO 7 — Packaged build smoke test

1. Rode `pnpm --filter @jarvis/desktop build:dist`.
2. Esperado: termina sem erro, cria dir `apps/desktop/release/`.
   - Nota: se `build:dist` falhar em Linux sem as deps nativas de FPM/AppImage, pule para verificar só o `win-unpacked`/`linux-unpacked` dir.
3. Rode `bash apps/desktop/scripts/smoke-packaged-build.sh`.
4. Esperado: `[smoke] PASS` com 4 .onnx encontrados em `release/{os}-unpacked/resources/wakeword-models/`.
5. Se Windows: instale o `.exe` gerado (ou rode o unpacked diretamente) e repita VERIFICAÇÃO 1 no artefato instalado.
6. Se wake word funciona no instalador → extraResources + runtime path resolver corretos.
