## v1.3 Requirements — Final Status

### Scaffolding & Infrastructure

- [x] **INFRA-01**: apps/backend-ts existe no monorepo pnpm com package.json, tsconfig.json e pnpm scripts funcionais
- [x] **INFRA-02**: Node.js 22.x LTS verificado e TypeScript 5.6+ instalado com strict mode habilitado
- [x] **INFRA-03**: .npmrc configurado com `shamefully-hoist=true` para evitar falhas de build de native modules
- [x] **INFRA-04**: Express HTTP server responde em http://localhost:8001 com GET /health retornando {"status":"ok"}
- [x] **INFRA-05**: Dockerfile multi-stage para backend-ts (build + runtime) seguindo padrão do Python backend
- [x] **INFRA-06**: docker-compose.yml atualizado com serviço backend-ts na porta 8001 com health checks

### Multi-LLM & Agent Core

- [x] **LLM-TS-01**: createLLM(provider, config) factory function suporta LM Studio, Claude e OpenAI via LangChain.js 1.x
- [x] **LLM-TS-02**: LM Studio conecta via ChatOpenAI com basePath configurável via .env (LMSTUDIO_BASE_URL)
- [x] **LLM-TS-03**: Validação no startup verifica que todas @langchain/* packages compartilham mesma versão de @langchain/core 1.x
- [x] **LLM-TS-04**: ChatSession class com método send(message) async retorna resposta do LLM via streaming
- [x] **LLM-TS-05**: @langchain/langgraph implementa ReAct agent loop (Reason → Act → Observe)
- [x] **LLM-TS-06**: POST /chat retorna resposta JSON completa do agent
- [x] **LLM-TS-07**: GET /chat/stream retorna Server-Sent Events com tokens incrementais

### Memory & Persistence

- [x] **MEM-TS-01**: Drizzle ORM schema define tabelas conversations, messages, tool_calls, user_profile matching Python schema
- [x] **MEM-TS-02**: better-sqlite3 conecta ao banco SQLite em ./data/jarvis.db com pragmas idênticos ao Python
- [x] **MEM-TS-03**: MemoryManager class salva mensagens no SQLite com timestamp e conversation_id
- [x] **MEM-TS-04**: ChromaDB JS client conecta ao banco em ./data/chroma com collection "memories"
- [x] **MEM-TS-05**: Transformers.js gera embeddings via Xenova/all-MiniLM-L6-v2 (mesmo modelo que Python sentence-transformers)
- [x] **MEM-TS-06**: Semantic search retorna mensagens relevantes via ChromaDB query com threshold de similaridade
- [x] **MEM-TS-07**: User profile persiste no SQLite e é injetado no contexto de cada conversa

### PC Control Tools

- [x] **TOOL-TS-01**: FileManager tool (read/write/delete files) via handlers Linux com Zod schema para inputs
- [x] **TOOL-TS-02**: AppLauncher tool (start/stop apps) com validação de processo
- [x] **TOOL-TS-03**: SystemControl tool (volume, brightness, shutdown) via platform-specific libraries
- [x] **TOOL-TS-04**: WindowManager tool (list/focus/close windows)
- [x] **TOOL-TS-05**: ProcessManager tool (list processes, CPU/memory stats)
- [x] **TOOL-TS-06**: ScreenAnalyzer tool (screenshot capture)
- [x] **TOOL-TS-07**: Tool confirmation mechanism pergunta confirmação para ações destrutivas (delete, shutdown, kill)
- [x] **TOOL-TS-08**: Tool audit log grava todas tool calls no SQLite com timestamp, tool_name, inputs, outputs, success
- [x] **TOOL-TS-09**: ToolExecutor class registra todas tools com @langchain/langgraph e executa com error handling

### Voice Pipeline

- [x] **VOICE-TS-01**: nodejs-whisper transcreve áudio WAV 16kHz para texto
- [x] **VOICE-TS-02**: Transformers.js TTS (Speecht5) + ElevenLabs TTS — provider abstraction com fallback
- [x] **VOICE-TS-03**: *Deferred to v1.4* — Porcupine wake word (requer AccessKey; opção alternativa: openwakeword)
- [x] **VOICE-TS-04**: POST /chat/audio aceita multipart upload de áudio WebM/WAV e retorna transcrição + resposta
- [x] **VOICE-TS-05**: VoiceManager class orquestra STT → ChatSession → TTS pipeline

### Validation & Cutover

- [x] **VAL-01**: E2E test suite envia mesmos inputs para Python (8000) e TypeScript (8001) backends
- [x] **VAL-02**: Comparison assertions validam que resposta de texto é semanticamente equivalente
- [x] **VAL-03**: Tool calls comparison valida que mesmos tools são chamados com mesmos inputs
- [x] **VAL-04**: SQLite state comparison valida que mensagens/tool_calls/profile são idênticos após cada request
- [x] **VAL-05**: ChromaDB embeddings comparison valida que embeddings têm >95% cosine similarity
- [x] **VAL-06**: Performance benchmarks mostram TypeScript latency ≤110% do Python
- [x] **VAL-07**: Gateway feature flag (`X-Backend-Version: ts`) roteia requests para TypeScript backend
- [x] **VAL-08**: Gradual cutover: text chat → TS, depois voice → TS, depois tools → TS
- [x] **VAL-09**: Python backend marcado deprecated após validação completa (período observação dispensado)
- [x] **VAL-10**: apps/backend-py removido do monorepo e Docker Compose após validação final
