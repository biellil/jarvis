## Layout & Structure

### Settings Window Dimensions

- **Size:** 480px width × 520px height
- **Resizable:** `false` (fixed size)
- **Frame:** `true` (native OS title bar, unlike orb)
- **Behavior:** `hide()` on close, reopen via tray "Settings" menu item
- **Position:** Center of screen or last position from previous session

### Form Structure

**Three vertical sections with clear separation:**

1. **Push-to-Talk (PTT)**
   - Label: "Push-to-Talk"
   - Hotkey display input (readonly) — shows current hotkey (e.g., "Ctrl+Space")
   - Button: "Record" — captures next key press
   - Status text: "Press any key combination..." during recording (color: rgba(255, 255, 255, 0.6), font-size: 12px)
   - Separator line below

2. **Voice (TTS)**
   - Label: "Text-to-Speech"
   - Dropdown: "Provider" — options: "Murf.ai" | "ElevenLabs"
   - Input field: "API Key" — password-masked (`type="password"`) if desired, or plaintext (UX decision: plaintext for simplicity per CONTEXT.md)
   - Status text: "Active: {provider}" (color: cyan-500, font-size: 12px)
   - Separator line below

3. **Transcription (Whisper)**
   - Label: "Speech-to-Text Model"
   - Dropdown: "Model" — options: "Auto (by VRAM)" | "Tiny" | "Base" | "Small" | "Medium" | "Large v3 Turbo"
   - Help text: "Auto: {detected_model} ({vram_mb}MB VRAM)" (color: rgba(255, 255, 255, 0.5), font-size: 12px)
   - Separator line below

### Button Bar

- **Save button** (primary CTA)
  - Label: "Save"
  - Position: Bottom-right
  - Color: Background #1F2937 (gray-800) → hover: #06B6D4 (cyan) with text white
  - Padding: 8px 16px
  - Border-radius: 6px
  - Font: 14px, weight 500
  - Margin: 16px from bottom, 16px from right
  
- **Cancel button** (secondary)
  - Label: "Cancel"
  - Position: Bottom-left of Save button
  - Color: Background transparent, border 1px rgba(255, 255, 255, 0.2) → hover: border rgba(255, 255, 255, 0.4)
  - Padding: 8px 16px
  - Border-radius: 6px
  - Font: 14px, weight 500
  - Margin: 16px from bottom, 16px from left (relative to Save)

## Form Interaction & Validation

### Hotkey Input (PTT Section)

**Normal state:**
- Input: readonly, displays current hotkey (e.g., "Ctrl+Space")
- Button "Record": clickable, background #1F2937, text white, border 1px rgba(255, 255, 255, 0.2)
- Button label: "Record"

**Recording state (after "Record" clicked):**
- Input: readonly still, text color rgba(255, 255, 255, 0.7), blinking cursor effect (optional)
- Button: "Recording..." (disabled appearance, cursor not-allowed)
- Status below input: "Press any key combination..." (color: cyan-500, font-size: 12px)
- Duration: Timeout after 5 seconds or on Escape key — revert to normal state
- Conflict detection: If duplicate hotkey detected (already assigned to widget hotkey), show toast error: "Hotkey already in use by another command"

**After valid key sequence:**
- Input updates to new hotkey display (e.g., "Alt+J")
- Button reverts to "Record"
- Status disappears

### TTS Provider Dropdown

**Normal state:**
- Label: "Provider"
- Options: ["Murf.ai", "ElevenLabs"] — display as radio-style dropdown or select
- Current selection: highlighted, bold or background color #1F2937
- API Key input field below: enabled, focus-able

**On selection change:**
- Input field clears (or optionally retains old value for user to edit)
- API Key field ready for input
- Live validation: On blur, check if API key is non-empty (not persisted until Save clicked)

### API Key Input

**Normal state:**
- Placeholder: "Paste your API key here..."
- Type: `text` (plaintext per CONTEXT.md — could be `password` in future for v2 security)
- Border: 1px rgba(255, 255, 255, 0.2)
- Focus: Border color rgba(6, 182, 212, 0.8), box-shadow 0 0 8px rgba(6, 182, 212, 0.3)
- Height: 36px (8px padding + 14px font + 6px internal rhythm)

**Validation (on Save):**
- If empty: Toast error: "API key cannot be empty"
- If valid (non-empty): Proceed to save flow

### Whisper Model Dropdown

**Normal state:**
- Label: "Model"
- Default: "Auto (by VRAM)" — displays "Auto: base (8192MB VRAM)" below
- Options: ["Auto (by VRAM)", "Tiny", "Base", "Small", "Medium", "Large v3 Turbo"]
- Help text below: "Auto: {detected_model} ({vram_mb}MB VRAM)" or "Manual: {selected_model}" (color: rgba(255, 255, 255, 0.5), font-size: 12px)

**On manual selection:**
- Help text updates to show "Manual: {model_name}"
- No additional validation needed — model change takes effect on next STT call

## Interaction States & Transitions

### Save Flow

1. User clicks "Save"
2. Validation runs:
   - Hotkey: Check for duplicates (widget hotkey, existing global shortcuts)
   - API key: Check non-empty if TTS provider selected
   - Model: Always valid (auto or manual selection)
3. If validation fails: Toast error + form remains open with focus on invalid field
4. If validation passes:
   - Toast "Settings saved" appears (2s auto-close)
   - Window hides (not closed — allows instant re-open from tray)
   - Main process updates:
     - Hotkey registration via `changeHotkey()` / `changePttHotkey()`
     - TTS provider/key: calls `reinitializeTTS()` on voiceHandler (live reload)
     - Whisper model: stored in `whisperModelOverride` in electron-store

### Cancel Flow

1. User clicks "Cancel"
2. Window hides (no changes persisted)
3. Form retains last-saved values (no in-memory form state loss across open/close cycles)

### Window Lifecycle

- **Open:** Via tray "Settings" item → create window if first time, or show() if exists
- **Close:** User clicks X button → window.hide() (not destroy)
- **Re-open:** Via tray "Settings" → load current values from electron-store into form fields

## Accessibility & Responsive Behavior

- **Tab order:** PTT section → TTS section → Whisper section → Save/Cancel buttons (logical flow top-to-bottom)
- **Keyboard support:**
  - `Tab` / `Shift+Tab` for field navigation
  - `Enter` on focused "Save" button to submit
  - `Escape` in "Record" mode to cancel hotkey capture
  - `Escape` in dialog to cancel (same as Cancel button)
- **Screen reader hints:**
  - Each input field has `aria-label` describing its purpose (e.g., "PTT hotkey, currently Ctrl+Space")
  - Buttons have clear labels, no icon-only buttons
  - Status messages use `role="status"` for dynamic updates
- **Reduced motion:**
  - No animations on form elements
  - Toast appears instantly (no slide-in animation)
  - Focus transitions via instant outline, no fade effects

## Notes for Planner & Executor

### For Planner

- **Window creation:** Check `apps/desktop/src/main/index.ts` for `BrowserWindow` pattern; new settings window should follow same security hardening (contextIsolation, sandbox, preload)
- **Vite multi-page:** Verify `vite.config.ts` entry point logic; settings.html should be parallel to `renderer/index.html`
- **IPC channels:** Define `settings:get`, `settings:save`, `settings:test-hotkey` in `apps/desktop/src/main/ipc/` (settings.ts exists, expand it)
- **Store schema:** Add to `StoreSchema` in `apps/desktop/src/main/store.ts`:
  - `ttsProvider: "murf" | "elevenlabs"`
  - `ttsApiKey: string`
  - `whisperModelOverride?: "tiny" | "base" | "small" | "medium" | "large-v3-turbo" | "auto"`

### For Executor

- **Hotkey recording widget:** Use `ipcRenderer.send()` to main process to subscribe to `globalShortcut` events during recording (or use keyboard event listener in renderer with validation in main)
- **Hotkey conflict detection:** Main process maintains registry of registered hotkeys; check against `changeHotkey()` and `changePttHotkey()` before registration
- **TTS live reload:** After save, main process calls `voiceInput/tts/index.ts` factory (check if it exposes `reinitialize()` method or create one)
- **Toast persistence:** Form should NOT close window until user confirms in toast; window.hide() only after "Settings saved" toast appears
- **Persist cancel state:** On Cancel or window hide, form fields revert to last-saved electron-store values (do NOT use local React state for persistence)
