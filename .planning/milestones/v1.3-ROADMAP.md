## Goal

Unificar toda a stack JARVIS no monorepo pnpm/node, migrando o backend Python para TypeScript gradualmente enquanto mantém ambos rodando em paralelo até validação completa.

## Key Accomplishments

1. **TypeScript backend (apps/backend-ts)** scaffoldado e em produção com Express 5 + Node 22 LTS na porta 8001
2. **Multi-LLM factory com LangChain.js 1.x** — paridade com Python: LM Studio, Claude, OpenAI via config-based switching
3. **Memory layer completa**: Drizzle ORM + better-sqlite3 + ChromaDB JS + Transformers.js embeddings — schema idêntico ao Python
4. **Agent runtime com `@langchain/langgraph`** + `createReactAgent` + 9 PC control tools integradas + streaming SSE
5. **Voice pipeline completo**: STT (nodejs-whisper) + TTS (ElevenLabs/Speecht5 fallback) + PTT Electron end-to-end
6. **Python backend removido** — gateway hardcoded para TypeScript, src/jarvis/ deletado, Docker Compose com 2 serviços apenas

## Key Decisions

| Decision | Context | Outcome |
|----------|---------|---------|
| LangChain.js 1.x (não 0.3.x) | 0.3.x entrou em modo manutenção Nov 2025 | ✓ Correto |
| z.coerce.number() para BACKEND_TS_PORT | process.env retorna string | ✓ Correto |
| Runtime version validation vs build-time | Captura issues de Docker/deployment | ✓ Correto |
| configuration: { baseURL } para LM Studio | LangChain.js 1.x pattern (não basePath) | ✓ Correto |
| Port 8001 para TypeScript backend | Python 8000, Gateway 3000 — sem conflito | ✓ Correto |
| Backend gera payloads, Electron executa | Separação de responsabilidades mais limpa | ✓ Correto |
| Sem período de observação (VAL-09) | User decidiu não usar mais Python | ✓ Decisão certa |
| .env não commitado (gitignore) | Segurança — edição local sem expor segredos | ✓ Correto |
