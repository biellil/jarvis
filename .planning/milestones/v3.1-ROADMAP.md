# Milestone v3.1: Distribution & Cleanup

**Status:** ✅ SHIPPED 2026-05-14
**Phases:** 68-71
**Total Plans:** 15 (13 entregues + 2 deferred com path-to-resume registrado)

## Overview

Milestone focada em preparar o JARVIS para distribuição multi-plataforma e em fechar débitos de configuração acumulados nas versões 2.x:

- **Settings UI Simplification (SIMP):** Settings UI deixa de gerenciar provider LLM, API keys (Gemini/OpenAI/Anthropic) e LM Studio URL — toda configuração passa pelo `.env`. Seção "Servidor MCP" inteira removida (toggle e lista de clientes). Migração automática `electron-store` → `.env` (com chmod 0600 POSIX) no primeiro boot pós-v3.1.
- **MCP Server Removal:** JARVIS deixa de expor MCP Server (stdio transport + 5 tools `recall_memory`, `list_files`, `openFile`, `openFolder`, `viewContent`). MCP Client permanece intacto — JARVIS continua consumindo servers MCP externos configurados via `.env`.
- **Multi-Platform Distribution (DIST):** electron-builder configurado para Windows (NSIS installer + portable), macOS (.dmg universal arm64+x64) e Linux (AppImage). Scripts `pnpm dist:win|mac|linux` no root. Preflight valida wine/mono/whisper-models/.env.example antes de empacotar.
- **Whisper Model Override Fix (WBUG):** Bug crítico corrigido — `selectWhisperModel` agora honra override explícito do usuário em vez de cair sempre em "medium". Opção "auto" removida do dropdown; default 'base'. Matriz 5×3 de testes de regressão.

## Milestone Summary

**Key Decisions:**
- Settings UI vira read-only para LLM/MCP: backend é source of truth, frontend não decide modelo (D-SIMP-01)
- Migração automática preserva configs do usuário no upgrade — sem prompt, sem perda (chmod 0600 POSIX para o `.env` migrado)
- MCP Server eliminado inteiro em vez de mantido com toggle off — reduz superfície de ataque e simplifica o boot
- Whisper "auto" removido da UI: usuário escolhe explicitamente; default `base` cobre 95% dos casos
- Multi-plataforma sem code signing: aceita SmartScreen (Windows) / Gatekeeper (macOS) workaround documentado no README, evita custo de cert (~US$300/ano) para uso pessoal
- Plans 71-04 (Linux smoke) e 71-05 (Windows UAT) deferred para backlog com path-to-resume completo em vez de bloquear a milestone

**Issues Resolved:**
- Bug WBUG-01: whisper carregava "medium" mesmo com override explícito do usuário — fixed em P68
- Settings UI poluída com configs que pertencem ao backend (provider, API keys, LM Studio URL) — limpa em P70
- Boot do JARVIS carregava MCP Server stdio mesmo quando ninguém o consumia — removido em P69
- Sem caminho de distribuição: usuário precisava clonar repo + `pnpm dev` para usar JARVIS — resolvido por P71 (NSIS/dmg/AppImage)
- README sem instruções de build/install por plataforma — documentado em P71-06

**Issues Deferred:**
- DIST-04 Linux smoke test → backlog 999.3 (requer host com display)
- DIST-01/DIST-02 Windows UAT → backlog 999.4 (requer PC Windows físico)
- Testes do app desktop pendentes (cobertura não-crítica) → backlog 999.2
- Auto-update via electron-updater + GitHub Releases → v3.2 (DIST-FUT-01)
- Code signing Windows EV cert + macOS notarization → v3.2+ (DIST-FUT-02)
- Linux .deb e .rpm packages → v3.2+ (DIST-FUT-03)
- GitHub Actions workflow para release tag → v3.2 (DIST-FUT-04)
- Watcher de `.env` em runtime para hot-reload → v3.2+ (atualmente exige restart)

**Technical Debt Incurred:**

- Config para Windows/Linux está completa mas binários jamais foram realmente gerados/distribuídos — só macOS foi exercitado
- Testes do desktop app têm cobertura desigual entre módulos (apontado em 999.2)
