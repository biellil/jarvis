  <behavior>
    Repository behavior:
    - create({ when: { delayMs: 1800000 }, message: "revisar PR" }) → inserts row with due_at = Date.now() + 1800000
    - create({ when: { atIso: "2026-05-10T09:00:00-03:00" }, message: "reunião" }) → inserts row with due_at = new Date(atIso).getTime()
    - list() → returns rows WHERE status IN ('pending','deferred') ORDER BY due_at ASC
    - cancel({ id: 1 }) → UPDATE status='cancelled' WHERE id=1
    - fuzzyFind({ query: "PR" }) → returns rows WHERE message LIKE '%PR%'

    Zod validation behavior (D-06):
    - delayMs must be int, positive, max 2592000000 (30 days ms)
    - atIso must be valid ISO 8601 with timezone (z.string().datetime())
    - message must be 1..500 chars

    Tool return strings (D-07) — pt-BR:
    - createReminderTool success with delayMs: "Lembrete criado pra daqui {human-time}: {message}."
      where human-time is "30 minutos" for 1800000ms, "2 horas" for 7200000ms, "1 dia" for 86400000ms
    - createReminderTool success with atIso: "Lembrete criado para {dd/MM às HH:mm}: {message}."
    - listRemindersTool empty: "Nenhum lembrete pendente."
    - listRemindersTool with items: "1. {message} (em {human-time})\n2. ..."
    - cancelReminderTool success: "Cancelado: {message}."
    - cancelReminderTool not found: "Não achei lembrete com esse texto."
    - cancelReminderTool ambiguous: "Encontrei mais de um lembrete:\n1. {msg1}\n2. {msg2}\nQual você quer cancelar?"
  </behavior>
  <implementation>
    **types.ts:** Export Reminder interface (id, due_at, message, kind, status, created_at, fired_at, deferred_until), createReminderInputSchema and cancelReminderInputSchema Zod schemas, ProactiveEvent discriminated union (same as ipc-types but backend-specific).

    **repository.ts:** `RemindersRepository` class with static methods using `db` singleton from `../memory/db.js`. All methods are synchronous (better-sqlite3 is sync). create() method takes `CreateReminderInput` and inserts; list() returns pending+deferred rows; cancelById(id) updates status; fuzzyFind(query) returns rows with LIKE.

    **tools.ts:** Three `tool()` functions from `@langchain/core/tools`. Each never throws — errors returned as pt-BR string. createReminderTool converts delayMs/atIso to due_at, calls repository.create(), returns formatted confirmation. listRemindersTool calls repository.list(), formats as numbered pt-BR list. cancelReminderTool calls repository.fuzzyFind(), handles 0/1/N+ cases.

    **session/tools.ts:** Import and re-export the three new tools. The wrapAllPcTools wrapping happens in chat-session.ts (not here) — just export them as factory functions accepting RemindersRepository or db dependency.

    **Human-readable time:** Implement `msToHumanPtBR(ms: number): string` that returns "X minutos" (< 60min), "X horas" (< 24h), "X dias" (>= 24h).
  </implementation>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool input → backend | LLM-generated JSON passed to tool schema — Zod validates before any DB operation |
| Tool output → LLM | Tool return strings echoed by LLM to user — must not contain format injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-01 | Tampering | createReminderTool schema | mitigate | Zod validates delayMs: int, positive, max 2592000000 (30 days ms); message: min 1, max 500. Rejects outside bounds before DB insert. |
| T-67-04 | Injection | RemindersRepository | accept | Drizzle uses parameterized queries exclusively — `db.insert(reminders).values({...})` never interpolates strings into SQL. |
| T-67-05 | Injection | listRemindersTool | mitigate | Tool output is a formatted string consumed by LLM. Truncate message to 500 chars (enforced at creation), do not add any LLM-parseable markup that could be interpreted as instructions. Format: plain numbered list only. |
</threat_model>
