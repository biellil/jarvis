## Validated Requirements

### Infrastructure Setup (PYSETUP)

- [x] **PYSETUP-01** — User can run `uv sync` in `apps/desktop-py/` to install all Python dependencies without system-level configuration
  - *Outcome: Validated. pyproject.toml + uv.lock committed; 19 packages resolved cleanly on Windows/Python 3.12*
- [x] **PYSETUP-02** — User can start the Python desktop client via `pnpm dev:desktop-py` from project root
  - *Outcome: Validated. Script wired in root package.json → `uv run python -m jarvis_desktop`*
- [x] **PYSETUP-03** — `.gitignore` and `.env` updated with Python-specific entries
  - *Outcome: Validated. venv/, .pytest_cache/, .env.example with GATEWAY_URL all committed*
- [x] **PYSETUP-04** — User preferences persist across sessions in `~/.jarvis/config.json`
  - *Outcome: Validated. JarvisConfig with load_config/save_config; auto-creates with defaults on first run*

### Terminal Chat (PYCHAT)

- [x] **PYCHAT-01** — User can type messages in the terminal and receive streaming responses token-by-token from the gateway
  - *Outcome: Validated. SSE streaming via urllib.request; tokens print immediately via rich.Console*
- [x] **PYCHAT-02** — Client verifies gateway health at startup and shows a clear error message if unreachable
  - *Outcome: Validated. check_health() called in run_with_health_check(); sys.exit(1) with clear message*
- [x] **PYCHAT-03** — User can see the current session's conversation history in the terminal
  - *Outcome: Validated. All tokens printed to console; history persists in terminal scroll buffer*

### Speech-to-Text (PYSTT)

- [x] **PYSTT-01** — User can trigger audio recording via a configurable hotkey (PTT) and have speech transcribed locally via faster-whisper singleton
  - *Outcome: Validated. pynput GlobalHotKeys with configurable ptt_key (default Ctrl+Shift+Q); singleton with threading.Lock*
- [x] **PYSTT-02** — User can select the Whisper model (tiny/base/small/medium/large-v3-turbo) via config; model loads on startup
  - *Outcome: Validated. init_stt(model_size) at startup; reload_model() in /config menu for hot-swap*
- [x] **PYSTT-03** — Client detects end of speech automatically via VAD; silence threshold configurable
  - *Outcome: Validated. record_until_silence() with faster-whisper VAD; silence_threshold_ms in JarvisConfig*

### Text-to-Speech (PYTTS)

- [x] **PYTTS-01** — JARVIS speaks responses aloud via Kokoro offline TTS (no API key; 350MB model downloaded on first run)
  - *Outcome: Validated. KPipeline with sounddevice playback; model downloads on first init*
- [x] **PYTTS-02** — Client falls back to ElevenLabs cloud TTS when Kokoro is unavailable or fails
  - *Outcome: Validated. _elevenlabs_speak() with elevenlabs SDK; automatic fallback in speak()*
- [x] **PYTTS-03** — Client falls back to Murf.ai as second cloud TTS fallback when ElevenLabs also unavailable
  - *Outcome: Validated. _murf_speak() with murf SDK; second fallback in speak() chain*
- [x] **PYTTS-04** — User can enable "local-only mode" in config to disable all cloud TTS providers
  - *Outcome: Validated. config.local_only=True skips cloud providers; uses Kokoro only*

### Voice Modes (PYMODE)

- [x] **PYMODE-01** — User can activate JARVIS via "Hey JARVIS" wake word (openwakeword offline, default threshold 0.7)
  - *Outcome: Validated. _wake_word_loop() with openwakeword ONNX backend; model auto-downloaded on first run*
- [x] **PYMODE-02** — User can use always-listening mode — VAD detects speech continuously without wake word
  - *Outcome: Validated. _always_listening_loop() with Model(vad_threshold=0.5, inference_framework="onnx")*
- [x] **PYMODE-03** — User can use PTT mode — configurable hotkey starts/stops recording
  - *Outcome: Validated. _ptt_loop() with pynput.GlobalHotKeys; D-06 blocking via tts.is_speaking()*

### Minimal UI (PYUI)

- [x] **PYUI-01** — Terminal displays a persistent status line: `[MODE] [MODEL] [STATE]` via rich
  - *Outcome: Validated. rich.Live with Layout; set_state() wired at 6 transition points across tts/voice_modes/chat*
- [x] **PYUI-02** — User can access a terminal config menu to change Whisper model, TTS provider, and voice mode without restarting
  - *Outcome: Validated. /config command in chat_loop(); 3-field menu; stt.reload_model/tts.set_provider/voice_modes.switch_mode*

## Deferred (Not Completed in v3.2)

- Runtime mode switching without restart — implemented via /config menu (exceeded original scope)
- Retry with exponential backoff on gateway failure — deferred (health check covers MVP)
- Packaging as standalone binary (PyInstaller/uv build) — future milestone
- Multi-turn voice listening window post-TTS — future milestone
- PC control tools in Python client — future milestone

## Out of Scope (Confirmed)

| Feature | Reason |
|---------|--------|
| ORB animation | No graphical UI in this client |
| LangChain/LangGraph in Python client | LLM stays in backend-ts; client is thin HTTP wrapper |
| Local SQLite/ChromaDB | Memory lives in backend-ts; client is stateless |
| Screen vision / image analysis | Electron-only |
| PC control tools | Stays in backend-ts |
| Settings GUI window | Terminal config menu sufficient for MVP |
