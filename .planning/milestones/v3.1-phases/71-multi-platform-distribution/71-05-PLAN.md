<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wine sandbox ↔ build host | wine roda makensis.exe via interpretação binária; sem privileged execution. Escopo limitado a build dir. |
| Windows SmartScreen ↔ unsigned .exe | Windows 11 24H2 mostra warning porque .exe não é signed (DIST-FUT-02 deferred) |
| NTFS ACL ↔ `%APPDATA%\JARVIS\.env` | Windows NTFS inherits ACL from parent dir — user-scoped por default (não precisa chmod) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-71-03 | Repudiation | Unsigned NSIS installer triggers SmartScreen warning | accept | DIST-FUT-02 (code signing) deferred to v3.2. README (Plan 71-06) explicitly walks user through "More info" → "Run anyway". User opt-in to bypass for personal use. |
| T-71-12 | Tampering | Wine bug introduces non-deterministic NSIS output | accept | Wine 9.x is stable for makensis use case (electron-builder maintainers verify cross-build path). User validates the produced .exe in physical Windows in Task 3 — any wine bug surfaces at install time. |
| T-71-01-win | Information Disclosure | `.env` in `%APPDATA%\JARVIS\` accessible to other Windows users | mitigate | NTFS ACL inherited from `%APPDATA%\` (user-scoped by default in Win 10+). Verified in Task 3 via `icacls`. No chmod 0o600 needed (POSIX-only). |
| T-71-13 | Tampering | Portable .exe extracted to `%TEMP%/{uuid}` — could be hijacked by another process between extract and run | accept | Windows OS-level mitigation: `%TEMP%/{uuid}` paths are user-scoped + ACLed. Personal use accepted risk. Research Pitfall 4 documents the `%TEMP%` behavior. |

</threat_model>
