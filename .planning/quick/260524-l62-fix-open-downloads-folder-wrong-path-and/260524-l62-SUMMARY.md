# Quick 260524-l62: Fix open Downloads folder wrong path and message not showing in terminal

**One-liner:** Corrigidos dois bugs no cliente desktop — open_folder recebia path vazio do LLM e abria home; resposta do JARVIS não aparecia no terminal por live_paused aninhado e label orphaned.

## Changes

### Task 1: open_folder path guard + LLM description
- `pc-tools.ts` createOpenFolderTool: description do campo `path` reescrita para instruir o LLM a usar nomes simples ("downloads", "home") em vez de `"~"` que não está no alias dict
- `pc_control.py` open_folder(): guard para path vazio/whitespace — levanta `ValueError` antes de tentar resolver, evita abrir home silenciosamente

### Task 2: _live_started flag em ui.py
- Adicionada variável `_live_started: bool = False` ao estado de módulo
- `init_ui()`: seta `_live_started = True` após `_live.start()`
- `cleanup_ui()`: seta `_live_started = False` após `_live.stop()`
- `live_paused()`: usa `was_started = _live_started` em vez de `_live is not None` — chamadas aninhadas (inner quando outer já parou) são no-ops
- `get_input()`: usa `_live_started` para decidir se precisa parar/reiniciar o Live

### Task 3: label [jarvis] com primeiro token em chat.py
- `_read_sse_stream()`: parâmetro `main_stream: bool = False` substitui `first_prefix_printed`; quando `main_stream=True`, label é impresso inline com o primeiro token — nunca fica orphaned por eventos agênticos intermediários
- `_stream_response()`: removido `console.print(_LABEL_JARVIS)` antecipado; passa `main_stream=True` para `_read_sse_stream`
- `_await_input()`: usa `_ui._live_started` em vez de verificar `_ui._live` diretamente (consistente com nova API de ui.py)
