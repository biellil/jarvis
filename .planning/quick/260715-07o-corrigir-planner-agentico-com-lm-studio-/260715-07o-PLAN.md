<objective>
Corrigir o erro do planner agêntico com LM Studio: `generatePlan()` chama
`llm.withStructuredOutput(planSchema)` sem opções, cujo método default (`functionCalling`)
envia `tool_choice` em formato OBJETO (`{ type: "function", function: { name: "..." } }`).
O LM Studio rejeita esse formato com HTTP 400 (`Invalid tool_choice type: 'object'.
Supported string values: none, auto, required`), o que faz `generatePlan` lançar e o
`plannerNode` (graph.ts) cair no fallback "Não consegui planejar essa tarefa." — o turno
agêntico nunca processa a mensagem do usuário quando o provider ativo é LM Studio.

Root cause e fix já confirmados via curl real contra o LM Studio do usuário (não
re-investigar): o método `jsonSchema` de `withStructuredOutput` — que envia
`response_format: { type: "json_schema", json_schema: {...} }` — funciona perfeitamente
(plano JSON conforme ao schema retornado). O método `jsonMode` NÃO é suportado por essa
versão do LM Studio. A versão instalada de `@langchain/openai` (1.4.3, confirmada em
node_modules) aceita `withStructuredOutput(schema, { method: 'jsonSchema' })` e produz
exatamente esse `response_format` — sem ambiguidade de nome de opção.

Fix travado (provider-aware, threading via config já existente): quando o provider ativo
é `'lmstudio'`, `generatePlan` passa `{ method: 'jsonSchema' }` para `withStructuredOutput`.
Para todos os outros providers (incluindo quando `provider` é omitido), a chamada
permanece EXATAMENTE `llm.withStructuredOutput(planSchema)` — sem segundo argumento —
preservando o comportamento atual (`functionCalling`) para OpenAI/Anthropic/Gemini/
OpenRouter, que hoje funcionam. `ChatSession` já rastreia o provider ativo em
`this._activeProvider` (Fase 63, D-02, usado hoje só para checar suporte a visão) — este
fix reaproveita esse campo, sem introduzir configuração nova.

O caminho do executor (`createReactAgent` em chat-session.ts, chamado com `tools` mas sem
`toolChoice`) já usa `tool_choice: 'auto'` (string) por default do LangGraph — o teste curl
do usuário confirmou que o LM Studio aceita esse formato. Este plano formaliza essa
verificação com um grep automatizado, sem alterar o executor.

Purpose: turnos agênticos funcionam com LM Studio sem regredir OpenAI/Anthropic/Gemini/
OpenRouter — "faz a alteração do erro sem querer o OpenAI" (requisito do usuário).
Output: `generatePlan`/`buildTaskGraph`/`ChatSession` provider-aware + testes cobrindo os
dois branches (lmstudio → jsonSchema; demais → default inalterado).
</objective>
