<objective>
Corrigir o hang do planner agêntico com LM Studio quando structured output (`json_schema`)
é solicitado sobre uma conexão STREAMING. Contexto: a Quick 260715-07o já corrigiu o HTTP 400
trocando `withStructuredOutput(planSchema, { method: 'jsonSchema' })` para lmstudio — correção
necessária mas insuficiente. O `llm` usado pelo planner (criado em `llm/factory.ts`) é
construído com `streaming: true`. Isso faz `generatePlan()` disparar uma requisição
STREAMING com `response_format: json_schema`, e o LM Studio trava nela — SSE vazio, o lock
de sessão nunca é liberado, a requisição nunca completa.

Root cause e fix já confirmados via teste real + pesquisa web (docs oficiais do LM Studio +
bug tracker) — NÃO re-investigar, apenas formalizar em código:
- curl manual, não-streaming, do mesmo request `json_schema` retorna JSON perfeito
  instantaneamente; o backend (streaming) trava na mesma requisição.
- Docs oficiais de structured output do LM Studio só mostram exemplos com `stream:false`.
- Bug tracker do LM Studio reporta modelos presos em geração infinita sob constraints de
  schema quando `maxTokens` não é definido, e `json_schema` + streaming retornando vazio.

Fix travado (somente LM Studio — não tocar no comportamento de OpenAI/Anthropic/Gemini/
OpenRouter): dar ao planner um modelo DEDICADO não-streaming (`streaming: false`) com um
cap de `maxTokens` (~512) como cinto de segurança contra geração infinita, quando o provider
ativo é `'lmstudio'`. O `llm` principal (streaming:true, usado para token streaming do
executor) permanece intocado. Para os demais providers, `plannerLlm` é `undefined` e
`generatePlan()` cai de volta no `llm` de sempre — zero mudança de comportamento.

Efeito colateral esperado (não é regressão, é reforço do fix de TTS anterior): com a chamada
do planner não-streaming, os tokens do planner deixam de vazar para o stream SSE de
`messages` — já era o comportamento desejado desde a Quick 260714-wrr.

Purpose: turnos agênticos com LM Studio completam a geração do plano de forma confiável, sem
regredir nenhum outro provider.
Output: `createPlannerLLM()` em `llm/factory.ts` + threading via `graph.ts` → `chat-session.ts`
→ `index.ts`, com testes cobrindo os dois branches (lmstudio → não-streaming+maxTokens;
demais → undefined/fallback).
</objective>
